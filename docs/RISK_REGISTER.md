## 风险评分矩阵 Risk Scoring Matrix

```
          概率 (Probability)
          低(1)    中(2)    高(3)
影 高(3)  │  中3  │  高6  │ 极高9 │
响 中(2)  │  低2  │  中4  │  高6  │
力 低(1)  │  低1  │  低2  │  中3  │
```

**风险等级:**
- 🟢 低 (1-2): 监控即可
- 🟡 中 (3-4): 需制定应对计划
- 🔴 高 (6): 立即制定缓解措施
- ⛔ 极高 (9): 上报业主，优先处理

## 风险清单 Risk Register

### 技术风险 Technical Risks

---

**R-T01: App Store审核被拒**
| 属性 | 详情 |
|------|------|
| 概率 | 中(2) |
| 影响 | 高(3) |
| **风险分** | **🔴 高(6)** |
| 原因 | Apple审核严格，隐私政策/UI要求/功能说明不足 |
| 影响 | 上线延期2–4周，影响客户承诺 |
| **预防措施** | 提前W12提交，参照Apple HIG设计指南，准备完整隐私政策，预留审核缓冲期 |
| **应对方案** | 根据拒绝原因快速修改；同时优先确保Android先上线 |
| 责任人 | Frontend Lead + PM |
| 监控频率 | 提交后每日 |

---

**R-T02: 积分计算精度Bug**
| 属性 | 详情 |
|------|------|
| 概率 | 中(2) |
| 影响 | 高(3) |
| **风险分** | **🔴 高(6)** |
| 原因 | 积分规则复杂（等级倍率×服务金额×促销叠加），边界案例难以覆盖 |
| 影响 | 客户积分错误→信任危机，可能导致积分欺诈 |
| **预防措施** | PointsEngine 100%测试覆盖率；每次计算使用数据库事务；实现积分审计日志；独立运行积分对账脚本 |
| **应对方案** | 手动修正受影响账户；发布紧急补丁；向受影响用户补偿额外积分+道歉通知 |
| 责任人 | Backend Lead |
| 监控频率 | 每日自动对账检查 |

---

**R-T03: 推送通知到达率低**
| 属性 | 详情 |
|------|------|
| 概率 | 中(2) |
| 影响 | 中(2) |
| **风险分** | **🟡 中(4)** |
| 原因 | 用户禁用通知权限；Firebase配额限制；iOS后台推送限制 |
| 影响 | 预约提醒无效，用户爽约率上升 |
| **预防措施** | App首次启动友好引导开启通知；实现In-App备用通知；重要提醒同时发SMS |
| **应对方案** | 降级到SMS短信提醒；分析权限请求时机，优化引导文案 |
| 责任人 | Backend B + Frontend |
| 监控频率 | 每周分析到达率报告 |

---

**R-T04: 第三方API服务中断**
| 属性 | 详情 |
|------|------|
| 概率 | 低(1) |
| 影响 | 高(3) |
| **风险分** | **🟡 中(3)** |
| 原因 | Twilio/Firebase/AWS服务故障 |
| 影响 | OTP无法发送→用户无法登录；推送通知中断 |
| **预防措施** | 实现备用SMS供应商（如MessageBird）；本地缓存Firebase Token；设置服务监控告警 |
| **应对方案** | Twilio故障→切换备用SMS；Firebase故障→队列重试；通知用户替代联系方式 |
| 责任人 | DevOps + Backend B |
| 监控频率 | 实时监控（CloudWatch告警） |

---

**R-T05: 数据库性能瓶颈**
| 属性 | 详情 |
|------|------|
| 概率 | 低(1) |
| 影响 | 高(3) |
| **风险分** | **🟡 中(3)** |
| 原因 | 积分历史表数据量大；复杂JOIN查询；缺少合理索引 |
| 影响 | API响应慢→用户体验差→流失 |
| **预防措施** | W10完成数据库索引优化；引入Redis缓存热点数据；上线前做压力测试（500并发） |
| **应对方案** | 即时加索引；升级RDS实例；引入读副本分担查询负载 |
| 责任人 | Backend Lead + DevOps |
| 监控频率 | 每日慢查询日志审查 |

**R-P02: 需求范围蔓延 Scope Creep**
| 属性 | 详情 |
|------|------|
| 概率 | 高(3) |
| 影响 | 中(2) |
| **风险分** | **🔴 高(6)** |
| 原因 | 业主在开发过程中提出新需求（"能不能加个XXX功能？"） |
| 影响 | 进度延误，预算超支，团队士气低落 |
| **预防措施** | 初期签署明确的需求规格说明书（SOW）；建立正式变更管理流程；每个变更需评估影响 |

| 责任人 | PM |
| 监控频率 | 每次Sprint Review |

### 业务风险 Business Risks

---

**R-B01: 客户App注册率低**
| 属性 | 详情 |
|------|------|
| 概率 | 中(2) |
| 影响 | 高(3) |
| **风险分** | **🔴 高(6)** |
| 原因 | 客户不了解App好处；注册流程复杂；老年客户群数字化程度低 |
| 影响 | ROI无法实现，项目价值难以体现 |
| **预防措施** | 设计极简注册流程（≤3步）；员工主动引导注册；注册送200积分激励；店内展示二维码 |
| **应对方案** | 推出"店员代注册"辅助服务；举办积分翻倍活动；发放传统纸质会员卡作为过渡 |
| 责任人 | PM + 业主 |
| 监控频率 | 上线后每周注册数统计 |

---

**R-B02: 积分系统被滥用**
| 属性 | 详情 |
|------|------|
| 概率 | 低(1) |
| 影响 | 高(3) |
| **风险分** | **🟡 中(3)** |
| 原因 | 推荐码批量注册刷积分；签到脚本滥用；优惠码泄露 |
| 影响 | 积分贬值，商业损失 |
| **预防措施** | 手机号实名验证（OTP）；签到IP+设备指纹检测；推荐奖励需被推荐人完成首次消费才发放；管理员审计日志 |
| **应对方案** | 冻结异常账户；回收欺诈积分；加强验证机制 |
| 责任人 | Backend Lead |
| 监控频率 | 每日自动异常积分检测 |

---

**R-B03: 数据隐私合规风险**
| 属性 | 详情 |
|------|------|
| 概率 | 低(1) |
| 影响 | 高(3) |
| **风险分** | **🟡 中(3)** |
| 原因 | 澳洲隐私法(Privacy Act 1988)；收集生日/位置等敏感信息 |
| 影响 | 法律处罚，品牌声誉损失 |
| **预防措施** | 法律顾问审核隐私政策；数据最小化原则；敏感数据加密存储；用户数据删除功能 |
| **应对方案** | 立即停止违规数据收集；法律顾问介入；主动通知受影响用户 |
| 责任人 | PM + Tech Lead |
| 监控频率 | 上线前法律审查；每年定期审查 |
